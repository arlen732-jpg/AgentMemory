# web-site 通用規範

web-site 是從 demo-site 複製出來的全端版本。畫面、元件、樣式規範**全部沿用** [../demo-site/通用.md](../demo-site/通用.md)，本檔只記錄不一樣的地方。

## 技術棧（在 demo-site 之外新增的部分）

| 項目 | 選擇 |
|---|---|
| ORM | Drizzle ORM，Neon HTTP driver（`drizzle-orm/neon-http`） |
| 認證 | Auth.js v5（`next-auth@beta`）LINE OIDC，JWT session |
| MCP | `mcp-handler` + `@modelcontextprotocol/sdk`，參數用 zod 定義 |
| 腳本 | `tsx --conditions=react-server`（seed） |

## 目錄結構（新增的部分）

```
src/
├── auth.ts              Auth.js 設定（門禁、login_logs）
├── proxy.ts             頁面登入保護（Next 16 的 middleware 改名為 proxy）
├── db/schema.ts         Drizzle 資料表，長度要和 LIMITS 對齊
├── server/              只在伺服器端執行，開頭一律 import "server-only"
│   ├── db.ts            db()：延遲建立連線
│   ├── http.ts          ok / fail / ApiError / route() / assertValid / readJson
│   ├── session.ts       requireOwner()
│   ├── crypto.ts        備註加解密、通行碼產生與指紋
│   └── {功能}.ts        service 層，網頁 API 和 MCP 共用
├── app/api/{功能}/      Route Handler
└── lib/api.ts           前端 fetch wrapper（ClientApiError）
scripts/seed.ts          測試資料
drizzle/                 migration SQL（drizzle-kit generate 產生）
```

## 分層原則

邏輯和驗證放在 service 層，route 只負責「檢查登入 → 讀參數 → 呼叫 service → 回應」。這樣 MCP 工具呼叫同一個 service，就會走同一套驗證。

```
Route Handler（requireOwner）──┐
                               ├─→ server/{功能}.ts（驗證、DB）─→ db()
MCP 工具（Bearer 通行碼）──────┘
```

## 驗證

前端和後端用同一份 `lib/validation.ts`。後端先用 `cleanXxxInput()` 做 trim，再驗證，最後呼叫 `assertValid(errors)`；有錯就回 400，錯誤內容放在 `fields`。

```ts
const m = cleanMemoryInput(input);              // trim、去重複
assertValid(validateMemory(m, []));             // 欄位錯誤 → 400 + fields
await assertKeyFree(m.item, m.key, excludeId);  // 需要查 DB 的檢查放在 service
```

⚠️ 注意：超過長度要**拒絕**，不可以靜默截斷（DevGuidelines）。

## 錯誤處理

- 業務錯誤用 `throw new ApiError(ERROR_CODE.X, "給使用者看的訊息", fields?)`，由 `route()` 統一轉成回應。
- 其他錯誤由 `route()` 記錄 `e.message`，回 500 和通用訊息。
- ⚠️ 不可以把 request body 寫進 log（FSD §6.3）。

## 時間

- DB 欄位一律 `timestamp(..., { withTimezone: true, mode: "date" })`。
- 對外回傳時用 `toISOString()` 轉成 ISO 字串。前端顯示照舊透過 `lib/dates.ts`。

## 現在時間與預先渲染

Next 16 開了 Cache Components，build 時會預先渲染頁面。頁面在渲染階段讀 `Date.now()`（例：用 `startOfTaipeiDaysAgo()` 算期間）會讓 build 失敗。

- `(main)/layout.tsx` 已用 `<Suspense>` 包住頁面，讓內容在每次請求時渲染。新頁面放在 `(main)` 底下就不用再處理。
- ⚠️ 放在 `(main)` 以外、又要讀現在時間的頁面，要自己包 `<Suspense>`，或改在 `useEffect`／事件處理裡讀。

## MCP 工具（server/mcp.ts）

- 每個工具只呼叫 service 層，所以驗證規則和網頁 API 是同一套。
- 參數用 `z.object({...})` 定義，字串欄位的 `.max()` 對齊 `LIMITS`。
- handler 一律用 `run()` 包起來：`ApiError` 會轉成 `isError` 的文字回應，其他錯誤只回通用訊息。
- 時間參數用 `parseTime()` 解析，沒帶時區時當成 `+08:00`。
- 入口 `/api/mcp` 用 `withMcpAuth(..., { required: true })` 驗證 Bearer 通行碼。驗證失敗一律回 401，不說明原因。

## 列舉

錯誤代碼、通行碼狀態都定義成 `as const` 常數，寫入端一律引用常數，不寫字面值。

```ts
export const ERROR_CODE = { UNAUTHORIZED: "unauthorized", VALIDATION: "validation", … } as const;
```
